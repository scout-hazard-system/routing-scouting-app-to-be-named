Scout Navigation + Scanner Intel StackLocal-first navigation + scanner-intel platform with a hardened Java backend, Android/Android Auto clients, versioned Ollama model set, and deterministic pipeline for real-time traffic enforcement alerting.---Project ScopeThis repository is a complete vehicle-mounted intelligence stack designed for cross-country driving. It fuses:Layer	ResponsibilityNavigation Backend (`navigation/backend`)	Hardened Java HTTP server (zero external framework) serving routing, geocoding, map tiles, scanner stream fanout, mobile client mailbox, GPS tracking, and LLM provider diagnosticsScanner Pipeline (`navigation/pipeline`)	Real-time Broadcastify audio capture → Whisper STT → multi-stage LLM analysis (ALERT → VET → INTEL → NAV) → TTS spoken alertsChannel Selector (`navigation/pipeline/channel_selector.py`)	Deterministic + LLM-reranked Broadcastify channel selection by jurisdiction, distance, listener count, and service typeScout LLM Set (`llm/`)	Versioned, purpose-built Ollama models (`scout-core`, `scout-vet`, `scout-rank`, `scout-alert`, `scout-intel`, `scout-dev`, `scout-hermes-hc`) with strict output contractsAndroid / Android Auto (`navigation/android`)	Kotlin client with foreground service, media-session integration, and AutoCarApp manifestStack Orchestration (`stack/`)	`master` script, systemd units, Docker Compose, Tailscale mesh config, and graceful power-move helpersMap Infrastructure	PMTiles planet vector tiles, custom `ProprietaryMapEngine`, sharded text extraction (`ExportMapTextShards`)---Unique Functions & Scripts1. Multi-Stage LLM Pipeline (`navigation/pipeline/pipeline.py`)Lines 47–458 — The only known local-first pipeline that chains four distinct LLM tasks per transcript with hard contracts:```python# Flow per 12-second audio window:1. ALERT   → scout-vet1.0.8  → "ALERT: ..." | "IGNORE"2. VET     → scout-vet1.0.8  → "VET_PASS" | "VET_FAIL"   (gate on proposed alert)3. INTEL   → scout-vet1.0.8  → structured JSON (call_types, priority, locations, POIs, units, codes, summary)4. NAV     → scout-core1.0.8 → single TTS line ≤ 20 words  ("USE CAUTION AHEAD" fallback)5. CHAT    → scout-core1.0.8 → JSON {response, confidence, missing_data, evidence} for driver Q&A```Key guarantees:Every call gracefully falls back to base `qwen3:8b` with inline system prompts when scout models are missingStrict output contracts prevent parser drift (see `llm_set_client.py:32–108`)Cached model availability (5-min TTL) avoids repeated Ollama `/api/tags` calls2. Scout LLM Client (`llm/client/llm_set_client.py`)Lines 116–458 — Single authoritative client with:Function	Model	Contract`query_alert()`	`scout-vet1.0.8`	Returns `"ALERT: ..."` or `"IGNORE"``query_alert_vet()`	`scout-vet1.0.8`	Returns `"VET_PASS"` / `"VET_FAIL"``query_intel()`	`scout-vet1.0.8`	Returns fixed-schema JSON`query_nav()`	`scout-core1.0.8`	Returns one TTS line ≤ 20 words`query_chat()`	`scout-core1.0.8`	Returns `{response, confidence, missing_data, evidence}``llm_set_status()`	—	Reports Ollama health + model installation matrix`resolve_model()`	—	Prefers scout model, falls back to `qwen3:8b` with `used_fallback` flagAll calls include retries, timeouts, and structured diagnostics (`model`, `used_fallback`, `parse_error`).4. Hardened Java Backend (`navigation/backend/BackendServer.java`)~7,300 lines, zero dependencies — Notable subsystems:Subsystem	HighlightsSecurity Gate (`doFilter` path)	Query validation → global access enforcement → body-size limits → CIDR allowlist → protected endpoint classes → pull-token authScanner Fanout	`/api/pipeline/stream` (SSE) + `/api/mobile/stream` with per-client backpressureMobile Mailbox	`/api/mobile/client/{register,send,pull}` with token-bound pull, TTL, and message capsMap Engine	`ProprietaryMapEngine` renders PMTiles → PNG with OSM attribution watermark; `/api/map/scene`, `/api/map/render`, `/api/map/shard`Routing	`/api/platform/route/local`, `/api/platform/route/options` with geometry + unified indexLLM Diagnostics	`/api/platform/llm/status` reports scout model availabilityObservability	Structured `request_rejected` logs with phase/reason/status/method/path/remote5. Versioned Model Build & Evaluation (`llm/build/`)Script	Purpose`build_llm_set.sh`	Creates all `scout-*` models from Modelfiles using `ollama create -f`; pulls `qwen3:8b` base if missing; runs smoke tests for ALERT/INTEL/NAV/CHAT/VET/RANK`eval_llm_set.py`	Evaluates `eval_cases.json` against live models; supports `--alert-only`, `--intel-only`, `--threshold 0.9`, JSON output for CI6. Stack Orchestration (`stack/commands/master`)```bash./master start|stop|restart|status|health|stream|logs [pipeline|backend|frontend]|check|urls|prepare-move````prepare-move`: Graceful stop + `sync` before vehicle power loss`urls`: Prints Termius port-forwards for dashboard (8787) and backend (18080)`health`: Hits `/api/health` + frontend`keep_vehicle_stack_alive.sh`: Watchdog for systemd/user-service deployments7. Map Text Shard Export (`navigation/backend/ExportMapTextShards.java`)Extracts searchable text from PMTiles planet vector tiles into the `vlm_text_map_shards_chunked/` hierarchy (z/x/y shards) for LLM context injection.8. Android Auto Integration (`navigation/android/`)`CarAppService` + `NavigationCarAppService` for Android Automotive OSForeground media session for TTS ducking`MapFragment` with `ProprietaryMapEngine` tile renderer---Quickstart```bash# 1.
